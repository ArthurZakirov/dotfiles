# ⏱️ Effort and scope checkpoints

| When | Then |
| --- | --- |
| **Before potentially substantial human effort:** A new multi-step implementation, large review, ambiguous requirement, integration, or repeated debugging may consume material time for understanding, review, verification, decisions, coordination, or manual execution. Agent-only research or runtime does not count. | Read and apply the [effort checkpoint procedure](agents-md-references/effort-scope-checkpoints.md) **before** committing to the potentially costly step. Check early rather than waiting for evidence of an actual overrun. |
| **During focused technical problem-solving:** The user is troubleshooting unexpected behavior, failures between interacting systems, or repeatedly asking for explanations, walkthroughs, reviews, or simplifications without stable understanding. | Read and apply the [effort checkpoint procedure](agents-md-references/effort-scope-checkpoints.md) before further debugging or explanation, accounting for investigation effort, review friction, and remaining work. |
| **When the remaining budget, review cost, or scope fit is uncertain but a meaningful overrun is plausible.** | Surface an **early, explicitly tentative effort/scope warning** in the main response, including the concrete uncertainty and the decision needed, rather than silently classifying it as safe. A caution is not proof of scope creep and does not by itself halt independent, already-authorized work; apply the procedure's actual pause/approval rules. |
